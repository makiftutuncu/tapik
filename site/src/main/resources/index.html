Type-safe APIs in Kotlin

Write the contract once.
Let the build prove the rest.

tapik represents HTTP APIs as ordinary, immutable Kotlin values. Its DSL retains contract structure in types, catches invalid definitions during compilation, and generates targets without making OpenAPI the source of truth.

Kotlin first

Contracts read like Kotlin, compose like Kotlin values, and keep their useful information in Kotlin types.

02

Fail during the build

Invalid contracts and unsupported target features stop compilation or generation before runtime.

03

Generate many targets

Produce OpenAPI, Spring RestClient clients, and Spring WebMVC servers from the same contract.

A small contract

Ordinary values, precise types

Define an API in a contract artifact, then select targets in the consuming Maven build. tapik generates source early enough for application code to implement servers or invoke clients.

Open the runnable example → 
object Books : Api() {
    val list by
        get(root / "books")
            .output(
                Status.Ok with
                    jsonBody<List<Book>>()
            )
}
