= Type-safe APIs in Kotlin
:description: Define HTTP API contracts as ordinary, type-safe Kotlin values and generate OpenAPI, clients, and servers from them.

tapik lets you define an HTTP API once as ordinary Kotlin values, then use that contract to generate OpenAPI documents,
Spring RestClient clients, and Spring WebMVC servers.

The Kotlin definition remains the source of truth. tapik's DSL retains contract structure in inferred types, the Kotlin
compiler rejects invalid combinations, and every generation target checks whether it can faithfully implement the
features it receives.

== What tapik optimizes for

Compile-time feedback:: Invalid or incomplete definitions should fail while compiling or generating, not after an
application starts.
Kotlin-first contracts:: Contracts are immutable Kotlin values that can be named, shared, and composed without a
parallel metadata representation.
One contract, several uses:: Documentation, clients, and servers are outputs selected by the consuming build rather
than separate definitions that can drift.
