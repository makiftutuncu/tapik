= Generate a Spring WebMVC server
:description: Generate Kotlin server interfaces and Spring WebMVC controllers from tapik endpoints.
:page-aliases: generation/spring-webmvc.adoc, code-generation/server.adoc

For each selected API, the `spring-webmvc` target generates:

* a pure Kotlin `Server` interface implemented by application handlers;
* an internal generated Spring controller that owns mapping annotations, wire conversion, and delegation.

The handler interface contains application behavior. The controller handles Spring routes and HTTP conversion.

== Generate from a compiled API module

Application source must be able to implement the generated interface before it compiles. Put endpoints in an API module,
then generate from that module during `generate-sources`. Add the API dependency, WebMVC runtime, and Spring Boot
WebMVC starter. The example imports dependency versions through the tapik BOM:

Run at least `compile`:

[,shell]
----

----

For `Books`, generation writes `BooksEndpoints.kt` and `BooksServer.kt` below the configured package and a registration
descriptor below `META-INF/tapik/spring/webmvc/`. The first source owns the shared endpoint response types; the second
contains the public `BooksServer` interface and internal `BooksGeneratedController` adapter.

In Gradle, declare the API dependency on both `implementation` and `tapikApiDependency`, choose
`Mode.COMPILED_API_DEPENDENCY`, and configure `springWebMvc { ... }`. The plugin adds generated source and registration
resources to the ordinary main lifecycle. See xref:reference/gradle.adoc[Gradle reference] for the tested build.

== Implement the handler

The generated interface exposes the original API value and one abstract method per endpoint. Those methods return
top-level sealed response types from the shared endpoint-types source. The user-owned handler deals only with decoded
Kotlin inputs and typed outputs:

`BooksHandler` has no mapping annotations, `ResponseEntity`, encoded bytes, content negotiation, or adapter bean
configuration. A more complex endpoint would expose path variables, query parameters, headers, and a decoded body as
method parameters. The handler chooses one generated response alternative and supplies its body and headers.

== Let Spring Boot register the controller

`tapik-target-spring-webmvc` publishes Spring Boot auto-configuration through Spring's standard
`AutoConfiguration.imports` resource. On startup, the auto-configuration reads tapik's generated adapter descriptors,
finds a handler bean for each generated `Server` interface, and registers the matching internal controller bean. This
is deterministic descriptor discovery, not package scanning of APIs or controllers.

The example only needs an ordinary Spring Boot application and the `@Component` handler shown above:

[source,kotlin]
----
include::example$application/LibraryApplication.kt[]
----

For a server interface, Spring resolves the handler through ordinary constructor injection. A single compatible bean is
used automatically; `@Primary` or another configured candidate resolver can disambiguate multiple implementations. If
no handler exists or the candidates remain ambiguous, application startup fails with Spring's dependency diagnostic,
which names the generated adapter and handler types. One handler bean may implement several generated server interfaces
and receive a controller adapter for each one. Descriptor discovery does not depend on generated controllers being
inside the application's component-scan package.

== Use plain Spring

In a non-Boot Spring application, annotate a configuration class with
`@dev.akif.tapik.target.spring.webmvc.EnableTapikWebMvc`. It activates the same descriptor registrar and bean-selection
rules. The annotation registers generated adapters only; it does not enable or configure Spring WebMVC itself.

== Request and response boundary

The internal controller owns routes and Spring mapping annotations. It decodes path, query, and header strings with the
endpoint formats, validates required and fixed inputs, selects request-body media representations, and calls the
handler with Kotlin values. It converts decoding and media-type failures into the appropriate HTTP response before the
handler is invoked.

After the handler returns, the controller matches the selected response alternative, encodes its body and headers,
negotiates the response representation, and constructs the Spring response. The handler cannot return a status or body
shape outside the generated sealed hierarchy.

Response negotiation matches `Accept` parameter names and charset values case-insensitively, so
`text/plain;charset=UTF-8` matches a body declared as `text/plain;charset=utf-8`. Other parameter values remain
case-sensitive; equivalent double-quoted and unquoted values match. The most specific matching range determines a
representation's quality, including `q=0` exclusions. Equal-quality, equally specific matches follow body declaration
order.

== Ownership and naming

tapik owns the generated `Server` interface, internal controller, registration descriptor, and wire conversion. Your
application owns handler behavior, Spring bean annotations, dependencies, persistence, transactions, authorization,
and other application policy.

RestClient and WebMVC generation for the same APIs use the same package prefix and output directory. Their shared
endpoint types then have one physical source and one identity, allowing a handler to delegate to a generated client and
return its response directly.

The defaults are package prefix `dev.akif.tapik.generated`, suffix `Server`, and suffix `GeneratedController`; all three
are configurable. Each API gets its own namespace under the prefix, relative to the prefix's parent package. See
xref:reference/generation-options.adoc#_spring_webmvc[Spring WebMVC target options]. Use the compiled API layout
when the current application's handlers need to implement generated interfaces; same-module generation happens after
its ordinary source compilation.

Continue with xref:reference/troubleshooting.adoc#a_spring_handler_is_not_found[Spring handler troubleshooting] if a
mapping is absent at runtime.
