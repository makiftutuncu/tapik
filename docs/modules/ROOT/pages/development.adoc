= Development guide
:description: Build, test, and document tapik itself.

tapik is built with Java 25, Kotlin 2.4, Maven, and Kotest. The documentation toolchain additionally requires Node.js
20 or newer. Use the Maven Wrapper for the complete build:

[source,shell]
----
./mvnw verify
----

Public behavior is specified under `specification/` before implementation. Changes follow a red-green-refactor cycle
and keep each coherent green increment small.

To build a local documentation preview, first install the reactor artifacts needed by unified Dokka, build the website
assets and API reference, then run Antora:

[source,shell]
----
./mvnw -DskipTests install
./mvnw -f site/pom.xml package
npm ci
npm run docs:preview
----

The preview command verifies the Dokka integration, adds version-relative links from every API reference page back to
the user guide, and then renders the current worktree together with tagged documentation history. This makes the same
version selector and canonical historical paths available locally. The command fails with the required Maven command
when the unified API reference has not been built first.

The complete site is written to `site/target/site`. Documentation publication is release-based; a push to `main` does
not replace the stable site with unreleased content.

== Documentation checks

`npm run docs:preview` and `npm run docs:build` both run source-example checks, fail on Antora warnings (including
missing cross-references, include files, or snippet tags), and scan generated HTML for missing pages, internal links,
anchors, and assets. Each build clears old narrative output while preserving the current unified API reference, so
files left over from a previous build cannot hide a missing page. Run `npm run docs:check` to repeat only the HTML scan.

To exercise the rendered site in Chromium at desktop and mobile sizes:

[source,shell]
----
npx playwright install chromium
npm run docs:smoke
----

The suite starts its own loopback server on port `4173`; stop any existing server on that port first. It checks the
quickstart and API-reference round trip, version switching, search, sidebar navigation, and page width. Test output
lives under `site/target/browser-results`, with an HTML report under `site/target/browser-report`. Failed tests retain
screenshots and traces; CI uploads those diagnostics and requires the suite to pass before publishing documentation.

The historical documentation is read from local Git tags, so a shallow checkout must fetch the release tags before
building. CI checks out complete tag history automatically.

== Publishing a release

For artifact packaging, the external-consumer rehearsal, signing, and Maven Central publication, follow the
xref:releasing.adoc[release procedure]. The steps below cover documentation publication after the artifact release.

The `Publish documentation` GitHub Actions workflow is the only documentation publisher. It runs for a published,
non-prerelease GitHub release, and it can be started manually with the latest stable release tag when its publication
must be retried. It rejects an older, draft, or prerelease release so a retry cannot replace the latest API reference
with mismatched output. In both cases it checks out that exact tag with complete tag history; pull requests and pushes
to `main` only run the preview build.

The release tag, root Maven version, and `docs/antora.yml` version must identify the same release. For example, tag
`v0.6.0` requires Maven version `0.6.0` and Antora version `v0.6.0`. The workflow rejects a mismatch before building or
publishing the site.

The release build publishes the current guide and unified API reference at `/docs/` and `/docs/api/`. It also writes
the same release to `/docs/v0.6.0/` and `/docs/v0.6.0/api/`, using the actual release version, so those explicit URLs
remain available after a later release replaces the latest paths. Previously published versioned API references are
preserved during deployment.

After the Maven site build has produced the unified API reference, the production documentation build can be rehearsed
from a release checkout with:

[source,shell]
----
TAPIK_RELEASE_TAG=v0.6.0 npm run docs:build
----

The command validates the three version identities, renders the tagged Antora history and explicit current version,
and copies the already integrated API reference into the matching version directory.
