= Type safety
:description: Learn how tapik keeps endpoint details in Kotlin types and checks definitions before runtime.

tapik keeps each endpoint's path, query parameters, headers, request body, and responses in the Kotlin type inferred
from its DSL. Adding one of these details changes the type; tapik does not flatten endpoint definitions into a separate
metadata model.

tapik checks definitions at three points:

Kotlin compilation:: The DSL's types reject invalid combinations and incomplete endpoints.
Value creation:: tapik checks rules that depend on actual values, such as duplicate names.
Output generation:: Each output generator rejects endpoint features it cannot represent and reports where the problem
occurred.

You normally do not write these types yourself. Kotlin infers them from the endpoint definition.

OpenAPI is generated output. tapik does not use it to reconstruct endpoints.
