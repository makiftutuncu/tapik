= Targets and generated output
:description: Built-in target IDs, configuration keys, naming defaults, and artifact locations.

Every Maven execution selects one host-neutral target and passes string values under `targetConfiguration`. A target
rejects unknown keys and validates its values before producing artifacts. Relative artifact paths are resolved below
the execution's `outputDirectory`, which defaults to `target/generated/tapik`.

== OpenAPI

Target ID: `openapi`

The target produces one `DOCUMENTATION` artifact per selected API.

[cols="2,2,4", options="header"]
|===
|Option |Default |Meaning

|`version`
|Required
|Non-blank version written to the OpenAPI document's `info.version`.

|`format`
|`yaml`
|`yaml` or `json`.

|`pretty`
|`true`
|Whether JSON output is pretty-printed. Accepts only `true` or `false`.

|`componentNaming`
|`simple`
|`simple` uses an unqualified schema name; `qualified` derives the component name from its qualified schema name.

|`output`
|`\{api}.openapi.yml` for YAML; `\{api}.openapi.json` for JSON
|Relative output template. Every `\{api}` occurrence is replaced by the exact API ID.
|===

An explicit `output` overrides the format-specific default. When multiple APIs are selected, the template must still
produce unique paths or generation fails.

== Spring WebMVC

Target ID: `spring-webmvc`

The target produces Kotlin `SOURCE` artifacts plus runtime `RESOURCE` descriptors used to register generated
controllers. The tested application uses:

[source,xml]
----
include::example$application/pom.xml[tag=webmvc-execution]
----

[cols="2,2,4", options="header"]
|===
|Option |Default |Meaning

|`packageName`
|`dev.akif.tapik.generated`
|Valid Kotlin package prefix for per-API type namespaces.

|`serverSuffix`
|`Server`
|Valid Kotlin identifier appended to the API type name for the pure handler interface, such as `BooksServer`.

|`controllerSuffix`
|`GeneratedController`
|Valid Kotlin identifier appended to the API type name for the Spring adapter, such as `BooksGeneratedController`.
|===

With the example configuration, Kotlin sources begin below
`target/generated-sources/tapik-spring/com/example/library/generated/`. Registration descriptors use
`META-INF/tapik/spring/webmvc/` beneath the execution output and are packaged as runtime resources by the Maven host.

When both Spring targets use the same `packageName`, they must also use the same output directory. Both executions then
claim one shareable `BooksEndpoints.kt` path instead of placing duplicate declarations on separate compile roots.

== Naming and collisions

Spring targets keep readable simple names such as `BooksClient` and `BooksServer`. Each API gets its own namespace
under `packageName`, derived from its JVM class name relative to the configured package's parent, not `Api.id`.
For API `com.example.library.contract.Authors` and `packageName` set to `com.example.library.generated`, import
`com.example.library.generated.contract.Authors.AuthorsServer`: the shared `com.example.library` root appears only once.
Endpoint response types and multi-representation request-body types are top-level declarations in that namespace and
have the same fully qualified names regardless of which Spring targets are selected.

The source root is fixed by the configuration, never inferred from selected APIs. APIs outside that root retain their
full class identity beneath a reserved `_external` namespace, so external `contract.Authors` cannot collide with local
`com.example.library.contract.Authors`. A literal underscore in an API name is escaped, making that marker unambiguous.
A one-segment `packageName` such as `generated` has no parent root and retains the full API identity below it.

This policy is independent of API selection, declaration order, and whether generation runs in the contract module or
a consuming module. Two contract artifacts with different qualified API classes cannot silently emit the same generated
identity under the same prefix. Source paths, controller names, and WebMVC descriptor paths all use that namespace.

Dot-separated class-name segments retain ASCII letters and digits. Every other UTF-16 code unit becomes `_` followed
by four lowercase hexadecimal digits; an invalid resulting Kotlin identifier gets prefix `_k_`. Thus a nested
`Outer$Books` uses `Outer_0024Books`, while an actual underscore is encoded as `_005f` so it cannot collide with an
escape. API simple names and configured suffixes must remain valid Kotlin identifiers.

Changing an API's qualified class name, `packageName`, or a suffix changes its generated public identity. Treat such
changes as compatibility changes. The naming policy itself is also a compatibility contract. WebMVC server and
controller suffixes must differ; different targets for the same API must also use distinct suffixes when sharing a
prefix. Repeated API classes in one request are rejected. Local method and nested response-name collisions still use
deterministic numeric suffixes.

OpenAPI file templates use `Api.id`. API filters also use `Api.id`. This distinction lets a Kotlin type name determine
source declarations while the contract's stable API identity determines selection and documentation filenames.

== Artifact synchronization

All artifact paths are normalized relative paths; absolute paths, `.` or `..` segments, empty segments, backslashes,
and duplicate result paths are rejected. The Maven host writes them below `outputDirectory`, records execution
ownership outside packaged output, and logs each path.

After a successful regeneration, files no longer returned by that execution are removed, including generated nested
classes and registration descriptors after a package or suffix change. A failed generation keeps the previous
successful files and ownership state intact. See xref:reference/troubleshooting.adoc[Troubleshooting] for failure
stages and diagnostics.
