= Generation model
:description: Follow endpoints from Kotlin compilation to generated source, resources, or documentation.
:page-aliases: code-generation/index.adoc

tapik generation has three steps. The Kotlin compiler records which APIs are available. A selected target turns their
endpoint definitions into output files. Maven or Gradle writes those files into the project and connects generated
source and resources to the build.

[source,text]
----
Kotlin API definitions
        │ compiler records APIs
        ▼
     API registry
        │ host selects APIs and target
        ▼
    output files
        │ Maven or Gradle adds files to the build
        ▼
 generated sources, resources, or documentation
----

The targets do not depend on Maven or Gradle. Both build plugins use the same registry and targets, then connect the
returned files to their own build.

== Compilation records APIs

The tapik compiler plugin writes an xref:reference/compiler-registry.adoc[API registry] for each Kotlin module with
eligible `Api` declarations. It does not run endpoint code, search packages, or make copies of endpoint definitions.
The registry refers to the original Kotlin values.

The registry is packaged in the compiled API artifact. A consuming project can use endpoints from that dependency. The
build plugin combines visible registries, sorts APIs by `apiId`, and reports duplicate IDs.

== The host selects APIs and a target

Each execution chooses a target and may select APIs by exact ID. An empty include list selects every visible API;
exclusions then remove APIs from that selection. Unknown IDs or a selection with no APIs produce an error.

Targets are loaded through Java service providers. Each target checks its options and which endpoint features it
supports, then returns an ordered list of files. For example, source generators use the endpoint property's Kotlin
type directly. See xref:generation/custom-targets.adoc[Create a generation target] to add another output provider.

== Targets return artifacts

Every result contains relative file paths and file contents. Each file has one of three roles:

`SOURCE`:: Source code which the host makes available for compilation.
`RESOURCE`:: Runtime metadata which the host arranges to package with the application.
`DOCUMENTATION`:: Documentation such as an OpenAPI document.

Two files in one result cannot have the same path. Targets return files but do not write them. The build plugin decides
where files go, removes stale generated files, registers sources and resources, and selects when generation runs.

== Maven and Gradle are hosts

The Maven plugin exposes generation through its `generate` goal. By default, same-module generation runs at
`process-classes`, after the current module compiles. When reading a compiled API dependency, bind generation to
`generate-sources` so application code can use the generated source.

The Gradle plugin uses a `tapik` configuration block and one `tapikGenerate` task. Same-project generation runs after
main classes. Compiled API mode runs early enough for the project's main source to use generated types.
