= Release procedure
:description: Rehearse packaging, verify an external consumer, and publish an approved tapik release.

== Rehearse without publication credentials

Use Java 25 and run from the repository root:

[source,shell]
----
./mvnw -Prelease -Dgpg.skip=true -Dcentral.skipPublishing=true -Dtapik.release.rehearsal=true clean install
GRADLE=/absolute/path/to/gradle-9.1/bin/gradle ./scripts/verify-gradle.sh
./scripts/verify-gradle.sh
----

This runs the Maven suite, builds production source and Dokka HTML `javadoc` JARs, and installs the reactor locally.
Gradle verification additionally builds the standalone plugin, its marker, and the Gradle external-consumer example
from an isolated repository, with configuration-cache failures enabled at both supported Gradle endpoints (9.1 and
the 9.8 wrapper). Neither path signs, deploys, creates tags, or publishes a GitHub release. The manually dispatched
`Rehearse release` workflow runs the complete credential-free rehearsal.

The final example module stages only production artifacts into a fresh temporary Maven repository. It copies cached
third-party POMs/JARs to reduce downloads, excluding every artifact under `dev/akif`, then adds this build's artifacts.
Allow several gigabytes of temporary disk space. A custom local repository is taken from Maven settings; uncached
dependencies still require network access.

The external consumer copies the runnable example's source and tests, not its `target` directories. Its independent
parent POM supplies Kotlin/Spring/Kotest configuration without inheriting tapik's development build. The nested Maven
build verifies registries, OpenAPI generation, generated servers and clients, and their Spring behavior. `test-` and
`example-` tapik artifacts are not staged or needed by that consumer.

Inspect these files before approving the release:

* `example-application/target/release-rehearsal.txt`: temporary workspace location.
* `example-application/target/release-staged-artifacts.txt`: exact staged artifact inventory.
* `example-application/target/release-consumer.log`: external Maven output and test results.
* `target/gradle-verification/external-consumer.log`: external Gradle output and test results.
* `target/gradle-verification/external-consumer.txt`: retained external Gradle workspace location.
* `target/gradle-verification/repository/dev/akif/tapik-plugin-gradle`: staged Gradle implementation, sources, HTML
  API documentation, and POM.

The temporary workspace retains its consumer project, repository, and log after either success or failure; remove that
specific directory manually when no longer needed. CI retains the small diagnostic files for seven days.
Ordinary `./mvnw verify` runs the rehearsal helper tests but skips the expensive external build.

== Approve the release candidate

. Finish review and commit the intended changes. Run the clean rehearsal against that exact commit.
. Check all module/BOM versions, the Gradle implementation and marker versions, and migration notes. Maven `0.6.0`,
  Gradle `0.6.0`, Antora `v0.6.0`, and the eventual Git tag `v0.6.0` must agree; use the actual release version when
  preparing later releases.
. Build and check the documentation preview as described in xref:development.adoc[Development guide].
. Confirm that the staged inventory contains the parent, BOM, production POMs/JARs, source JARs, and HTML documentation
  JARs, but no non-production module artifacts.

The unsigned rehearsal does not prove signing-key access, Central namespace permissions, Gradle Plugin Portal
credentials, or remote publication.

== Sign and publish (release operator only)

Configure the Central Portal token in a Maven settings server named `central`, following the
https://central.sonatype.org/publish/publish-portal-maven/[Central publishing plugin instructions]. Configure a signing
key and GPG agent using the https://maven.apache.org/plugins/maven-gpg-plugin/usage.html[Maven GPG instructions].
Keep credentials out of repository files and command-line passphrases; tapik enables the plugin's best-practices mode.

After explicit release approval, verify Maven signing locally:

[source,shell]
----
./mvnw -Prelease -Dcentral.skipPublishing=true clean verify
----

Inspect the signatures and confirm the version is unused. The following command is a real remote publication, not
another rehearsal:

[source,shell]
----
./mvnw -Prelease clean deploy
----

The profile automatically publishes the reactor-wide Central deployment and waits for completion. If the command
fails after uploading, inspect its deployment status in Central before retrying; a timeout is not proof of failure.
Publish Maven Central artifacts before the Gradle Plugin Portal marker. A plugin marker must never become visible while
its matching `tapik-plugin-compiler`, runtime, or built-in target artifacts are unavailable from Maven Central. Verify
the implementation and marker metadata against the exact staged version, then publish the already tested Gradle
plugin candidate through the configured portal credentials.

After Maven Central confirms every dependency is available, supply Portal credentials through `GRADLE_PUBLISH_KEY`
and `GRADLE_PUBLISH_SECRET` and validate the already rehearsed plugin version without uploading it:

[source,shell]
----
GRADLE_USER_HOME=target/gradle-release-home ./plugin-gradle/gradlew -p plugin-gradle publishPlugins --validate-only \
  -PtapikRepository=/absolute/path/to/staged-repository \
  -PtapikVersion=0.6.0
----

Resolve every reported problem before removing `--validate-only` from that exact command to perform the real upload.

Published versions must not be overwritten. Fix a released defect in a new version.

Once Central publication is confirmed, create and push the matching release tag for the tested commit, then publish
the GitHub release. Its publication triggers the documentation workflow described in
xref:development.adoc#_publishing_a_release[Publishing release documentation]. Verify the public artifact coordinates,
latest documentation, and immutable version URLs before announcing the release. Do not publish a GitHub release while
its Maven artifacts are still unavailable.
