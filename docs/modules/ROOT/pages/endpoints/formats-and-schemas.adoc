= Formats and schemas
:description: Connect Kotlin values to wire representations and neutral schemas with tapik formats.
:page-aliases: contracts/formats-and-schemas.adoc

A `Format<Value, Representation>` combines a codec with a schema. The codec handles values on the wire; the schema
describes the same value to targets that need structural information.

== Formats for endpoint values

Path variables, query parameters, and headers use `StringFormat<Value>`, an alias for `Format<Value, String>`. Bodies
use `ByteArrayFormat<Value>` and carry their media type separately.

[[media-types]]
=== Media types

`MediaType` requires a concrete `type/subtype` value, not an `Accept` range; wildcards are rejected. It normalizes the
type, subtype, parameter names, and charset values to lowercase. Parameter order and equivalent quoting do not affect
equality, though normalized output retains parameter declaration order. Other parameter values remain case-sensitive.
For example, `Text/Plain;Charset="UTF-8"` equals `text/plain;charset=utf-8`.

Duplicate parameter names are rejected without regard to case. Syntax validation does not check whether a target
supports a media type or its charset.

`transform` catches exceptions thrown while converting the decoded value and returns a structured `DecodeResult`
failure. `transformOrThrow` is the explicit propagating variant. Both retain the original wire representation and
schema. `.named("BookId")` gives schema-aware targets a stable name they can reuse.

Every format also has `.repeated()`, which produces a list format, preserves element order, and accumulates decoding
errors. Repeated query parameters use this operation internally.

----

----

Return `DecodeResult.Failure` for invalid input so callers receive a structured decode error. Exceptions thrown by a
custom decoder or encoder propagate to the caller. Keep the schema aligned with the encoded representation; tapik does
not infer or verify a custom codec's wire shape. See the
link:{page-api-reference-url}tapik/dev.akif.tapik/-format/index.html[`Format` API reference] for the full API.

For a Kotlin enum, use `format.enumValue<BookState>()`. The resulting format writes and reads exact constant names and
publishes the same ordered names through `EnumSchema`; an unknown value becomes a structured decode failure listing
the allowed names. Convenience factories are also available as `path.enumValue<BookState>("state")`,
`query.enumValue<BookState>("state")`, and `header.enumValue<BookState>("X-Book-State")`. Each retains `BookState` in
the inferred endpoint type. Use `.named("BookState")` when targets should reuse the enum schema by name.

Body formats are opt-in. tapik provides JSON integrations for Kotlin serialization and Jackson 3. Each exposes
`jsonBody<Value>()`; pass its configured JSON instance as `format` and set `mediaType` when the body uses a vendor media
type. Their schema rules and customization options are described in the
xref:endpoints/formats/kotlin-serialization.adoc[Kotlin serialization guide] and
xref:endpoints/formats/jackson.adoc[Jackson guide].

== Neutral schemas

The core schema algebra is intentionally independent of OpenAPI and serialization libraries. It currently represents:

* scalar, enum, array, object, map, nullable, and reference schemas;
* required and deprecated object properties;
* ordered union alternatives with an optional discriminator and reference mapping.

Schemas themselves are untyped; the enclosing `Format<Value, Representation>` establishes the Kotlin relationship.
Format integrations derive these neutral values from user-owned models. Derivation fails when the chosen integration
cannot describe a type it must encode, rather than silently producing an incomplete schema.

Names are optional. Use `.named(...)` when a schema-aware target should reuse a schema; the target decides how to turn
that name into an external one. In OpenAPI, named structural schemas become components and unnamed structural schemas
stay inline. Reference schemas continue to point to their targets.
