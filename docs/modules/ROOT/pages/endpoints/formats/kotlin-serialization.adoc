= Kotlin serialization
:description: Configure tapik JSON formats and schema derivation for Kotlin serialization.

The `dev.akif:tapik-format-kotlinx` artifact provides JSON formats backed by Kotlin serialization. Use
`jsonBody<Value>()` from `dev.akif.tapik.format.kotlinx` for request and response bodies. Pass the configured
`kotlinx.serialization.json.Json` instance as `format` when you need custom serializer settings.

If your models use `@Serializable`, apply Kotlin's serialization compiler plugin at the same version as Kotlin. In
Maven, add `kotlin-maven-serialization` to `kotlin-maven-plugin` and enable its `kotlinx-serialization` compiler
plugin. Keep tapik's `tapik` compiler plugin enabled in the same project. In Gradle, apply
`org.jetbrains.kotlin.plugin.serialization` alongside Kotlin/JVM. These plugins generate serializers; tapik uses them
to encode values and derive schemas. See the xref:reference/maven.adoc[Maven] and xref:reference/gradle.adoc[Gradle]
references for tapik's compiler-plugin setup.

== Schema derivation

tapik derives neutral schemas from serializer descriptors. The same built-in scalar catalog handles primitive values
and standard Java time values wherever they appear. For example, `LocalDate` derives a `string` schema with `date`
format, while `Instant`, `OffsetDateTime`, and `ZonedDateTime` use `date-time`, including in nullable properties,
collections, and maps.

Object property names come from the serializer descriptor. tapik does not apply `Json.namingStrategy` when deriving an
ordinary object schema. If that strategy changes the names written on the wire, supply an explicit schema to
`jsonFormat` or `jsonBody` so documentation uses those wire names.

Schema derivation does not create a codec. For Java time values, provide an actual serializer whose descriptor
identifies the Java type.
Contextual descriptors do not derive automatically; register a schema for the descriptor or supply an explicit root
schema.

== Register schemas for custom types

`KotlinxSchemaRegistry` removes a trailing `?` from descriptor names before matching registrations. It passes the
resolved `SerialDescriptor` to schema providers. Registrations apply recursively to matching root values, object
properties, nullable values, collection elements, and map keys or values. For nullable values, tapik wraps the
registered schema in a nullable schema. Use `withSchemaProvider` when a schema depends on the resolved descriptor.

with different registries remain separate.

== Polymorphic values

tapik derives a `UnionSchema` for sealed and open polymorphic types with at least two alternatives. Sealed alternatives
come from the serializer and keep its declaration order. Open alternatives come from the finite list of registered
subtypes and are sorted by serialized name so generated schemas remain stable, regardless of registration order. Each
subtype must serialize as an object. tapik adds the configured discriminator as a required enum property to each
subtype schema and records the discriminator mapping on the union. `@JsonClassDiscriminator` sets the discriminator for
a sealed type; otherwise tapik uses `Json.classDiscriminator`.

The JSON format must use object polymorphism with `ClassDiscriminatorMode.POLYMORPHIC`. Array polymorphism, another
discriminator mode, a naming strategy on a polymorphic type, or a default provider for open polymorphism cannot be
represented and causes schema derivation to fail. A subtype also cannot declare its own property with the discriminator
name. `ClassDiscriminatorMode.ALL_JSON_OBJECTS` also prevents derivation of ordinary object schemas.

== Supply a schema directly

Pass `schema` to `jsonFormat` or `jsonBody` when an integration cannot derive the wire schema. The supplied schema
describes the entire root value, including nested custom behavior. It bypasses derivation and the registry but does not
configure or validate the codec. You are responsible for matching the schema to the serializer and deserializer.
Formats with an explicit schema are not stored in inferred-format caches.

See xref:endpoints/formats-and-schemas.adoc[Formats and schemas] for shared format behavior and neutral schema types.
