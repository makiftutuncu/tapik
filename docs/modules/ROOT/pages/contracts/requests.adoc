Headers may be required, optional, optional with a default, or fixed to a value. Names are validated as HTTP field
names and must be unique case-insensitively within an endpoint.

The generic `header("X-Request-Id", requestIdFormat)` constructor accepts optional `description` and `deprecated`
arguments. The resulting documentation is preserved by optional, defaulted, and fixed presence modifiers and is used
for request parameters and response headers in generated OpenAPI.

`.headers(headersOf(...))` is a one-time bulk initializer available only while the endpoint has no headers. After the
first header is present, `.header(...)` appends one definition at a time. Both preserve concrete types and declaration
order. `headersOf` requires between one and eight values; `noHeaders` represents the empty group.

== Request bodies

`.input(...)` can be called only while the endpoint has `NoInput`, making a second request input a compilation error.
One `Body<Value>` combines:

* the media type used for content negotiation;
* a `ByteArrayFormat<Value>` that decodes, encodes, and describes the value.

Format integrations supply builders such as `jsonBody<CreateBook>()`. The generic `body(mediaType, format)` builder is
available when defining another representation.

`MediaType(...)` validates a concrete HTTP media type immediately. Malformed syntax, duplicate parameter names, and
wildcards such as `application/*` are rejected. Its `value` and string representation use normalized spelling:
`MediaType("Text/Plain;Charset=\"UTF-8\"")` becomes `text/plain;charset=utf-8`. Type/subtype, parameter-name, and charset
casing do not affect equality; neither does parameter order or equivalent quoting. Other parameter values remain
case-sensitive, so multipart boundaries `A` and `a` are different. Parameter order is retained in rendered output.

`bodiesOf(...)` groups alternative media representations of one logical Kotlin type. Their media types must be
distinct. Adding `noBody` as the final alternative makes the complete request body optional; an endpoint with only
`noInput` has no request-body definition at all.

The body group is non-empty and preserves representation order. `noBody` may appear at most once and only last. The
request-body description belongs to the group as a whole, matching OpenAPI's model; set it in `.input(...,
description = ...)` or replace it with `.requestBodyDescription(...)`.
